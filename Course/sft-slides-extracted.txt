FINETUNINGFine-tuning is a technique where a pretrained model is adapted to a new, specific task by continuing its
training on a smaller, task-specific dataset. It leverages the knowledge learned from large-scale datasets
and adjusts the model's parameters to improve performance on the new task.

MODEL LOADERA model loader is a utility or function that allows you to load a pretrained model, its architecture, and the
associated weights (parameters) into memory so that you can use it for inference or further training
(fine-tuning).

-- 7 of 34 --

MODEL LOADERIn Hugging Face's Transformers library, there are two main categories of model loaders: Model-specific
loaders and AutoModel loaders.
1. Model-Specific Loaders
Definition: These loaders are tied to a specific model architecture. They are used when you know the
exact type of model you want to load (e.g., BERT, GPT-2, T5).
Example:
BertForSequenceClassification.from_pretrained('bert-base-uncased')
GPT2LMHeadModel.from_pretrained('gpt2')
T5ForConditionalGeneration.from_pretrained('t5-small')

-- 8 of 34 --

MODEL LOADER2. AutoModel Loaders
Definition: The AutoModel class and its variants automatically select the correct model architecture
based on the model identifier you provide. This loader abstracts away the need to specify the model
architecture explicitly, making it easier to switch between different model types.
Example:
AutoModelForSequenceClassification.from_pretrained('bert-base-uncased')
AutoModelForTokenClassification.from_pretrained('roberta-base')
AutoModelForCausalLM.from_pretrained('gpt2')

Similar to AutoModel, the AutoProcessor class is used for automatically selecting the appropriate
processor based on the type of model you are using. Different AutoProcessor classes are used for
different types of models (text, image, audio, etc.), and they combine the functionalities of tokenizers,
feature extractors, and image processors, depending on the model's input type.
Processor Types include: Tokenizer, Image Processor, Audio Processor, Multimodal Processor and
Audio-Text Processor.

Quantization is the process of reducing the precision of the weights or activations in a neural network
model. This technique is mainly used to make models smaller, faster, and more efficient, the model's
parameters (weights) are often stored as 32-bit floating-point numbers (FP32). Quantization reduces the
precision of these values, using lower-bit representations like 8-bit integers (INT8) or 16-bit floating-
point (FP16).

A Data Collator in Hugging Face prepares batches of data before feeding them into a model. It handles:
Tokenization (if not already tokenized)
Padding (ensuring all inputs in a batch have the same length)
Special formatting (e.g., adding masks, labels for training)
Applying Chat Templates (only for some specific collators)
Some data collators can be imported from specific library/framework such as transformers, unsloth, or
can be manually defined in a function. We don’t manually use collator but instead pass it to a trainer as
arguments.

PEFT (Parameter-Efficient Fine-Tuning) is a technique that fine-tunes only a small subset of model
parameters instead of the entire model. This makes training faster, less memory-intensive, and more
efficient, especially for large language models (LLMs).
PEFT
Learn More

-- 22 of 34 --

LoRA (Low-Rank Adaptation) is a parameter-efficient fine-tuning (PEFT) method that freezes the original
model weights and adds small trainable low-rank matrices to transformer layers. LoRA decomposes
weight updates into two small matrices A and B (rank "r" << full model size), so fewer parameters need
to be updated.
Original Weight Matrix: W of size (512 × 512)
LoRA Decomposition: Introduces two smaller matrices:
A of size (512 × 8) (low-rank dimension r = 8)
B of size (8 × 512)
The LoRA update is computed as:
W′=W+AB
where:
AB=[(512×8)×(8×512)=512×512]
Instead of updating 262,144 parameters (512 × 512), we now train only 8,192 parameters (512 × 8 + 8 ×
512), saving 97% of trainable parameters!

When fine-tuning a model, tracking Loss and Validation Loss is crucial for understanding how well the
model is learning and generalizing.
1. Training Loss (Loss)
It indicates how well the model is minimizing the difference between its predictions and the ground
truth.
A decreasing training loss usually means the model is learning.
However, an extremely low training loss could indicate overfitting, meaning the model memorized the
training data rather than learning general patterns.
2. Validation Loss
Unlike training loss, validation loss tells us how well the model generalizes to unseen data.
If validation loss is much higher than training loss, it suggests overfitting—the model is performing
well on training data but poorly on new data.
If both training and validation loss are high, the model may be underfitting, meaning it hasn't learned
enough.

A model checkpoint is a saved state of a model at a specific point during training. It includes the model’s
weights, optimizer state, and sometimes additional metadata like training step and loss. Checkpoints
allow you to:
Resume training if interrupted.
Save intermediate progress to avoid retraining from scratch.
Evaluate models at different stages to select the best version.
Deploy trained models for inference.
